# Design: TIPO Dashboard Mockup

## Frontend design plan (per frontend-design skill)

**Subject pinned:** 台灣專利事務所/企業 IP 承辦人員，每日核對數十至數百件專利年費期限，一次疏漏可能導致客戶專利權消滅。頁面唯一任務：3 秒內看出哪些案件快過期。

**Avoiding the default:** 不用 cream+terracotta、不用近黑+螢光、不用 broadsheet 零圓角。改走「官方登記簿 / 謄本」氣質，但用現代排版執行 —— 呼應 TIPO 公報、專利證書、印鑑的視覺語彙，而非通用 SaaS 儀表板。

### Color (named, hex)
- `--ink` `#16233F` 墨藍（品牌、標題、主要按鈕）— 呼應公文用印墨色
- `--paper` `#EFEEE7` 卷宗紙色（背景，偏冷灰而非常見的暖米色）
- `--seal` `#C23B2E` 印泥朱紅（signature accent：logo 印記、主要 CTA、日期尺「今日」標記 —— 唯一鮮豔色，用量極克制）
- `--status-alive` `#2F7A4F` 存續綠（沉穩，非螢光）
- `--status-grace` `#B8792B` 補繳琥珀
- `--status-dead` `#6E6C63` 消滅灰
- `--hairline` `#DAD7CC` 卷宗分隔線
- `--ink-muted` `#6B6A62` 次要文字

### Type (roles)
- Display（品牌標題/Hero）：Noto Serif TC — 呼應公報鉛字印刷的莊重感，僅用於頁首品牌與區塊大標
- Body/UI：Inter — 清晰中性，負責介面文字與中文內文搭配
- Data/Numeric（案號、日期、統計數字）：IBM Plex Mono — 等寬對齊，強調「這是精確法律資料，不是隨意文案」

### Layout
一頁式直向流程，四區塊皆為真實工作流步驟（上傳→比對→檢視→匯出），故合理使用編號 eyebrow（01 總覽 / 02 上傳比對 / 03 結果總覽）—— 這裡的順序是真實流程，不是裝飾。卡片使用小圓角（6px）非零圓角、非過度圓潤，呼應紙本登記簿的方正但可親。

ASCII 佈局概念：
```
┌───────────────────────────────────────────────┐
│ 01  TIPO 專利狀態智動化分析系統        [設定][範本]│
├───────────────────────────────────────────────┤
│ 總解析筆數 │ 存續中 │ 補繳/復權中 │ 已消滅/失敗   │
├───────────────────────────────────────────────┤
│ 02  上傳比對  拖曳區 ── 進度尺 ─────────────────│
├───────────────────────────────────────────────┤
│ 03  結果總覽  搜尋/篩選 ─────────────── [匯出]  │
│  案號 | 名稱 | 權人 | 年費有效 | 止日 | 狀態 | 尺│
└───────────────────────────────────────────────┘
```

### Signature: 日期尺（Date Ruler）
核心業務邏輯就是「今日落在哪一段日期區間」。把這個判斷邏輯本身畫成視覺：一條極簡水平尺，四個刻度＝年費有效日期／+6mo／+18mo／專利權止日，朱紅色圓點＝今日座標。這條尺同時出現在（a）表格列的迷你版（40px 寬 sparkline）與（b）Dialog 詳情的完整版＋刻度標籤。這是全頁唯一被記住的視覺裝置，且直接把 CLAUDE.md 的判定邏輯「翻譯」成圖像，而非裝飾性圖表。

### Motion
頁面載入：統計卡片依序 stagger fade-up（極短，120ms 間隔）。上傳比對：progress bar 以計時器模擬 45/100 筆跳動＋列表逐行 fade-in（模擬「即時抓取」）。不加多餘 hover 彈跳；日期尺的今日標記在 Dialog 開啟時做一次性 draw-in。Respect `prefers-reduced-motion`。

## Technical decisions
- UI primitives are hand-rolled (not the shadcn CLI) to avoid a network-dependent install step during the mockup phase; they follow shadcn's file/API conventions (`components/ui/button.tsx` etc. with `cva` variants) so a later `npx shadcn add` migration is a drop-in replacement, not a rewrite.
- Mock dataset (10 rows) is generated by feeding plausible `patent-edate`/`charge-expir-date` pairs through the real `evaluatePatentStatus()` — the badges shown are never hand-authored strings, so the demo cannot drift from the CLAUDE.md logic.
- No external state library; `useState`/`useMemo` only, matching mockup scope.
